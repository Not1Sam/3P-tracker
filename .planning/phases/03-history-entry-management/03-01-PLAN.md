**Step 1 — Create `src/utils/date-helpers.ts`** with these exported functions:

1. `formatDateHeader(date: Date): string` — Returns "Today" if isToday(date), "Yesterday" if isYesterday(date), "MMM d" if same year as now, "MMM d, yyyy" otherwise. Uses `format`, `isToday`, `isYesterday` from `date-fns`. Per D-03: date headers for list view grouping.

2. `formatEntryTime(date: Date): string` — Returns "h:mm a" for today entries, "MMM d, h:mm a" for older. Uses `format` and `isToday` from `date-fns`. Per D-04: entry card timestamp display.

3. `toLocalDateString(date: Date): string` — Returns "YYYY-MM-DD" using local date components (getFullYear, getMonth, getDate) with zero-padded month/day. This avoids timezone issues from toISOString() (Pitfall 6 from RESEARCH.md).

4. `groupEntriesByDate(entries: (PoopLogEntry | PissLogEntry)[]): Array<{ title: string; dateKey: string; data: (PoopLogEntry | PissLogEntry)[] }>` — Sorts entries by timestamp descending, groups by dateKey (YYYY-MM-DD), produces SectionList-compatible sections with title from `formatDateHeader`. Per D-03: chronological scroll with date headers.

**Step 2 — Create `src/services/history-service.ts`** with these exported functions:

1. `getCalendarMarkedDates(year: number, month: number): Promise<{ poopDates: Set<string>; pissDates: Set<string> }>` — Queries `getPoopLogsByDateRange` and `getPissLogsByDateRange` for the full month (startOfMonth to endOfMonth), extracts unique date strings via `toLocalDateString`. Only queries timestamp column for performance (Pitfall 1 from RESEARCH.md). Per D-01: calendar color-coded dots.

2. `getEntriesForDate(date: Date): Promise<{ poop: PoopLogEntry[]; piss: PissLogEntry[] }>` — Calls `getPoopLogsByDate` and `getPissLogsByDate`, returns separated arrays. Per D-02: day detail view data.

3. `getEntriesPaginated(limit: number, offset: number): Promise<(PoopLogEntry | PissLogEntry)[]>` — Queries both repos with limit/offset, merges and sorts by timestamp descending, returns top `limit` entries. Supports SectionList infinite scroll. Per D-03: list view data.

4. `getEntryById(id: string, type: LogType): Promise<PoopLogEntry | PissLogEntry | undefined>` — Dispatches to `getPoopLogById` or `getPissLogById` based on type. Per D-05: entry detail screen data.

5. `updateEntry(id: string, type: LogType, fields: { typeId?: number; colorId?: number; smell?: SmellLevel; comment?: string }): Promise<void>` — Dispatches to `updatePoopLog` or `updatePissLog`. Per D-06 + D-07: editable fields only.

6. `deleteEntryWithUndo(id: string, type: LogType, toastCallback: (msg: string, onUndo: () => void) => void, refreshCallback: () => void): Promise<void>` — Fetches entry via getEntryById, stores it for undo, deletes via deletePoopLog/deletePissLog, shows toast with 3s undo window using the existing Toast component pattern. On undo: re-creates the entry. After 3s: clears undo state. Per D-08 + D-09: delete with undo toast.

Import `LogType` from `@/types/logging`. Import repository functions from the correct paths.
